### 18.20 项目落地补充（v2.3，2026-10-15）

本节解决原文中影响计算正确性和可维护性的约束。原文仍保留完整产品愿景；本项目的阶段边界以批准的设计文件为准，禁止将首版交付称为完成全部 124 条 FR。

#### 18.20.1 部署与模块边界

首版采用模块化单体：一个 FastAPI 应用、一个本地数据库、一套 Svelte 客户端，重任务通过独立 worker 执行。§11.1 的服务首先作为逻辑领域边界；Kafka、Kubernetes、Neo4j、Milvus、Feast 和多服务网络通信按实际需求逐项引入。

业务依赖方向为 `API → application → domain`，数据库与外部 provider 实现 domain 声明的端口；domain 不导入 FastAPI、SQLAlchemy、厂商 SDK 或 UI。前端按功能目录拆分，页面只负责编排，指标与金融计算统一由后端返回。数据采集、优化器、模型、LLM 和券商均有明确接口，不能增加一个实现就复制业务流程。

#### 18.20.2 时间语义与标的身份

所有时间戳含时区，存储 UTC，交易日按市场日历解释。`as_of` 必须与知识口径一起记录：

| 口径 | 定义 | 用途 |
| ---- | ---- | ---- |
| `public_pit` | 公开披露时间不晚于 as_of，选择该时点已公开的有效修订版本；另固定本次数据版本 | 历史研究；允许后来补录真实历史资料，但必须声明来源是否具备修订历史 |
| `system_replay` | 同时要求披露时间与首次入库时间不晚于 as_of，并保留当时修订和撤回状态 | 还原本系统当时真正知道什么 |

§7.5 的双时间过滤对应 `system_replay`。禁止在今天首次导入历史数据后，仍用今天的 ingest_time 过滤声称能完成十年前的系统回放。缺少历史修订时显示覆盖缺口，不能用当前更正值冒充当时已知值。

财务源表记录报告期、披露时间、入库时间、来源和修订序号；快照查询按口径选择每个报告期的最后可见版本。`financials_pit.as_of = 某日` 仅适用于真实生成的快照表，不能代替可见版本选择。交易状态、行业归属、指数成分、股本与退市状态同样必须带有效期。

标的内部使用稳定 `security_id` 与交易所标识（如 XSHG/XSHE/XHKG/XNAS），展示代码和 provider 代码是映射字段。原 DDL 中裸 `code` 主键只是摘要示意，正式迁移必须防止跨市场代码冲突。

#### 18.20.3 成本、成交与账本

费用规则包括证券类别、市场、账户协议、币种、`valid_from/valid_to` 与来源。股票过户费示例为成交金额 0.01‰（0.1bp）双向，不能写为“深市免费”；卖方印花税 5bp 基准自 2023-08-28 起使用，历史回测按当日规则选取。佣金需说明是否已包含规费，避免重复收费。参见 [上交所费用说明](https://one.sse.com.cn/onething/gptz/)与[税务总局公告](https://shanxi.chinatax.gov.cn/web/detail/sx-11400-545-1780448)。

资金和数量使用 Decimal/数据库定点数，API 以十进制字符串传输；按费用项目定义舍入时点。特征矩阵和优化计算可用浮点，但结果转为订单前必须经过确定性的股数取整、费用和资金重验。账户分别记录现金余额、冻结现金、可用现金、可取现金、持仓、可卖数量和应收股利；回测与模拟盘共用账本与费用内核。

信号、委托与成交时间必须分离。收盘形成的信号最早次交易日执行；同日收盘成交要求证明信号在截止前可得。开盘成交容量禁止引用当日最终成交量；日线无法证明盘口排队与部分成交顺序，输出必须声明保守撮合假设。涨跌幅、最小单位、上市初期规则按市场/板块/证券状态/生效日读取，不能只按 ST 布尔值写死。

除息日确认应收，实际支付日释放现金；分红、送转、拆并股、配股、税费均写账本事件。退市不制造卖出成交。净值、可用资金与可变现估值分开报告，禁止用风险折价静默改写真实成交。

#### 18.20.4 写操作、安全与流式任务

金融写操作的幂等键由服务端校验，作用域至少含账户与操作；载荷规范化后保存摘要，同键异内容返回 409。订单创建、资金冻结、审计与事件 outbox 在同一数据库事务内完成；broker 调用通过可恢复状态机执行，不能宣称外部链路绝对 exactly-once。连接中断先查状态，再决定重试。

AI 建议单保存内容摘要、数据版本、风险规则版本、有效期与确认人。确认只能消费一次；提交前重新验证账户、资金、价格、可卖数量和风控。紧急停止立即禁止新单，再异步撤单并反馈失败/未知状态；恢复才需要强确认。离线交易只保存草稿，联网后重验并重新确认，不能自动回放交易队列。

本地后端只绑定 loopback，仍需会话令牌、Origin/Host 校验、CORS 精确白名单、文件大小限制与路径约束。外部服务端地址由受控配置指定，不能接受网页任意设置。密钥由后端或桌面安全存储持有，不写入前端包、数据库普通字段、日志、快照或 Git。

SAG 首版只执行白名单指标/DSL 编译的参数化查询。自由 SQL 后续引入时，除 AST 校验外须有只读数据库角色、允许的视图/函数集合、租户与时间过滤、超时/行数/内存限制；只读 SELECT 不等于安全，分类器不决定授权。

长任务持久化 `queued/running/succeeded/failed/cancelled` 状态、进度和取消请求。每个流事件带 run_id、递增 seq 与协议版本；断线后查询状态或按 seq 续传，禁止重开一次付费任务冒充续传。POST 流使用 fetch 解析 SSE，重连游标显式传入；浏览器 EventSource 仅用于适用的 GET 订阅。

#### 18.20.5 数据授权、研究证据与验收

Provider 描述数据授权、可覆盖市场/历史区间、最早可用时间、修订能力、时延、限额和质量状态。爬取可用不代表有商用或再分发授权；无密钥时用明确标识的合成数据/用户导入资料，不承诺全市场实时 SLA。北向披露规则已于 2024 年调整，不能把示例中的 2026 年个股/板块每日净流入默认视为公开可得真值，需逐指标验证授权与可得性；未知值返回 null。参见 [港交所披露调整说明](https://www.hkex.com.hk/News/Market-Communications/2024/2404122news?sc_lang=en)。

论文方法是候选方案，不是项目效果保证。每项引入须记录原文链接、版本、适用假设、实现许可、数据划分、基线和消融实验。收益、IC、攻击成功率、成本降低比例不可直接迁移为上线承诺。FATH 的正确编号为 [arXiv:2410.21492](https://arxiv.org/abs/2410.21492)，原编号 [2509.02718](https://arxiv.org/abs/2509.02718) 属于多模型路由论文。

性能指标必须声明机器、数据规模、并发、冷热缓存、样本量与统计窗口。研究模型发布需防泄漏的滚动样本外验证和概率校准，不能只用固定 IC 门槛替代基准对比。所有 FR 建立阶段、实现状态、验收证据与依赖映射，原 M/S/C 表作为产品愿景优先级保留。

#### 18.20.6 可维护性与项目输出

公开函数有类型与稳定命名；关键金融逻辑注释说明口径和原因。禁止全局可变业务状态、循环依赖、巨型路由文件和吞掉异常。配置集中校验，使用依赖注入和明确错误码；日志携带 trace_id，不记录密钥。Python 用 Ruff/格式化与类型检查，TypeScript strict、Svelte check、ESLint/Prettier；接口类型从后端 OpenAPI 生成并校验。

优先测试领域不变量与真实异常：资金守恒、费用基数、最小单位、T+1、幂等并发、同键异内容、未来数据、分红到账、退市与取消恢复。跨平台浮点运算以声明的误差界验收，固定数据/版本/seed 的同环境运行须可复现。

项目独立存放于 `stock-portfolio-client/`。GitHub 输出包括代码、锁文件、README、设计/接口/数据说明、示例配置、测试、CI 与运行/打包指引；密钥、个人持仓、授权行情、虚拟环境和构建缓存排除。原文缺少的软件许可证决策在发布前明确，不能擅自宣称开源授权。

Windows 桌面构建需要 Rust、MSVC Build Tools 与 WebView2；缺少时应记录浏览器开发版与 Windows 安装包的不同验收状态，不能只提交 Tauri 配置就称安装包已验证。GitHub 仓库地址、归属与可见性在首次上传时明确，尚未指定时只在本地准备可上传产物。

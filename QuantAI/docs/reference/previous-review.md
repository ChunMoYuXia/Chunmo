# 审阅报告：股票组合智能分析客户端 — 需求与技术架构文档

> 审阅日期：2026-10-15
> 审阅对象：v2.0 文档（4894 行，~325KB）
> 审阅方法：逐节通读 + 交叉引用核对 + DDL/SQL 审查 + 金融规则校验

---

## 一、审阅总评

该文档在整体架构完整度和工程深度上属于**行业领先水准**：124 条 FR 均带可测量验收口径；RAG/SAG/Agent 三层设计精准区分了"证据来源"与"计算来源"；PIT 治理贯穿数据-AI-回测全链路；成本吞噬量化与多周期决策树极具实用价值。但存在若干**事实性错误**（如印花税税率过时）、**内部矛盾**（成本基数混淆）、**DDL约束缺失**和**缺失章节**需修正。

**统计：严重 1 项 / 一般 6 项 / 建议 9 项 / 新增章节 7 个**

### 一般（6 项）

| 编号 | 位置 | 问题类型 | 问题描述 | 具体修订内容 |

| P3 | §10.2 Almgren-Chriss 公式 | 事实错误 | 公式标注"风险中性"，但含 λ>0 的 sinh 轨迹实为**风险厌恶(risk-averse)**解。风险中性(λ=0)轨迹为线性。 | "风险中性" → "风险厌恶 / risk-averse"。新增注释说明风险中性退化情况。**已应用。** |
| P4 | §10.14.6 "资金到账时间"行 | 逻辑矛盾+事实错误 | 同一单元格内"T+1 可用"与"当日可用但不可取"自相矛盾；"影响再平衡可买量"结论错误——A股卖出资金当日可买。 | 改为"A股卖出资金当日可用于买入(T+0买)，但不可取(T+1可取)；卖出所得可立即用于买入，不影响再平衡可买量"。**已应用。** |
| P5 | §10.13.6 成本吞噬量化 | 基期混淆 | "单边成本合计≈12–16bp（双边）"——标为"单边"却称"双边"，加总15.7bp与"双眼12-16bp"不符。 | 拆分买入/卖出单边成本，明确单边~10.5bp(买)/15.7bp(卖)，双眼约26bp。**已应用。** |
| P6 | §11.3 DDL `orders` 表 | DDL约束缺失 | `request_id` 标为"防重放"但无 DB 级唯一约束，仅靠应用层检查不够。 | 新增 `CONSTRAINT uq_orders_request_id UNIQUE (request_id)` 与部分唯一索引。**已应用。** |
| P7 | §11.3 审计哈希链 | 字段未定义 | `hash` 计算引用 `payload` 但表中无此列，实际应为 `before`+`after`。 | `payload` → `coalesce(before::text,'') || coalesce(after::text,'')`，新增 `payload_hash` 生成列。**已应用。** |
| P8 | §14.2 认证授权 | 安全设计缺失 | 仅有 `refresh_token`(7d, 可撤销)，未提及 Refresh Token 轮换(高危)。 | 新增 Refresh Token 轮换说明（旧 token 二次使用则吊销整个会话链）。**已应用。** |

## 六、总体评价

**优势：**
- PIT 治理、"AI 不做算术"、"AI 不下单"三大铁律贯穿全栈，合规底线清晰

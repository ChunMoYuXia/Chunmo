## 1. 引言

### 1.1 编写目的

本需求分析说明书旨在全面、准确地描述「多模型机器学习预测与智能决策」的功能需求、非功能需求、数据需求和接口需求，为项目的开发、测试、验收和维护提供基线依据。

**预期读者：**
- 项目开发人员（机器学习工程师、量化研究员）
- 系统测试人员
- 项目管理人员
- 系统运维人员

### 1.2 项目背景

项目一（智能可视化分析报表）生成了含技术指标的行情数据，但**单一模型无法判断预测的可靠性**。本项目在项目一的数据基础上，搭建**多模型对比框架**：让 3 个机器学习模型在历史数据上赛跑，通过**时序交叉验证**客观评估各模型表现，选出 Loss 最小的最优模型，并对最新数据进行涨跌预测，最后调用大模型生成**风控导向**的投资建议。

### 1.3 项目范围

**包含的范围：**
- 读取项目一清洗后的行情数据
- 特征与标签工程（时序严格切分，防数据泄露）
- 多模型训练（逻辑回归 / XGBoost / LightGBM）
- 时序交叉验证（TimeSeriesSplit）
- Log-Loss 与 AUC 评估、最优模型筛选
- 最新数据预测与上涨概率输出
- AI 风控导向投资建议
- 整合进项目一的 Streamlit（折叠面板排行榜）

**不包含的范围：**
- 回归式连续价格预测（本项目采用分类任务）
- 高频 / tick 级数据预测
- 超参数自动调优（当前仅用默认参数）
- 实盘自动交易执行

### 1.4 术语与缩略语

| 术语 | 说明 |
|------|------|
| Label | 预测目标（标签） |
| Feature | 特征（预测依据的输入变量） |
| TimeSeriesSplit | 时序交叉验证，保证训练集在验证集之前 |
| Log-Loss | 对数损失，衡量概率预测的校准程度 |
| AUC | Area Under Curve，曲线下面积，衡量排序能力 |
| LR | Logistic Regression，逻辑回归 |
| XGBoost | eXtreme Gradient Boosting，梯度提升树 |
| LightGBM | 微软的梯度提升树框架 |
| 数据泄露 | 用未来信息预测过去导致评估失真的问题 |

## 2. 项目概述

### 2.1 项目定位

本项目定位为**基于 A 股历史数据的涨跌分类预测与智能决策框架**。它通过多模型对比 + 时序交叉验证，评估模型在当前数据上的真实可靠性，选出最优模型输出上涨概率，并给出风控导向的投资建议，为投资决策提供概率化、可解释的依据。

### 2.2 项目目标

| 目标编号 | 目标描述 | 验收标准 |
|---------|---------|---------|
| G-01 | 构建特征与标签工程 | `X_train.shape` 与 `y_train.shape` 一致，无未来数据泄露 |
| G-02 | 搭建 3 模型擂台 | 训练逻辑回归、XGBoost、LightGBM 三模型 |
| G-03 | 时序交叉验证 | 用 TimeSeriesSplit（3 折）评估，训练集始终在验证集前 |
| G-04 | 指标评估 | 输出每个模型的 Log-Loss 与 AUC |
| G-05 | 筛选最优模型 | 自动选取 Log-Loss 最小（或 AUC 最大）的模型 |
| G-06 | 最新数据预测 | 用最优模型预测最新一天上涨概率 |
| G-07 | AI 投资建议 | 生成风控导向的投资建议与风险因素 |
| G-08 | 整合 Streamlit | 在项目一页面增加排行榜折叠面板 |

### 2.3 用户特征与角色

| 角色 | 权限 | 典型用户 |
|------|------|---------|
| **投资者** | 查看模型排行榜、上涨概率与投资建议 | 个人投资者 |
| **量化研究员** | 分析模型评估结果、调整特征与模型 | 量化学习者、研究员 |
| **开发者** | 配置数据、模型与 LLM，运行系统 | 项目开发者 |

> 本项目为项目一的扩展模块，延续其单用户本地工具定位，不设多角色权限体系。

### 2.4 系统架构概述

系统采用**数据驱动 + 模型评估 + AI 决策**的分层架构，建立在项目一的数据成果之上：

```
┌──────────────────────────────────────────────────────────┐
│              Streamlit 界面（项目一页面内扩展）             │
│        排行榜折叠面板 · 最优模型高亮 · AI投资建议           │
└──────────────────────┬───────────────────────────────────┘
                       │ 调用
┌──────────────────────▼───────────────────────────────────┐
│                  AI 投资顾问层                             │
│      Prediction + PE → Prompt模板 → LLM → 风控建议         │
└──────────────────────┬───────────────────────────────────┘
                       │ 概率
┌──────────────────────▼───────────────────────────────────┐
│               最优模型筛选层                               │
│       Log-Loss最小/AUC最大 → 最新数据预测 → 上涨概率        │
└──────────────────────┬───────────────────────────────────┘
                       │ 评估指标
┌──────────────────────▼───────────────────────────────────┐
│             多模型擂台（训练 + 时序交叉验证）                │
│    LR(基准) · XGBoost · LightGBM → Log-Loss/AUC          │
└──────────────────────┬───────────────────────────────────┘
                       │ 特征/标签
┌──────────────────────▼───────────────────────────────────┐
│               特征与标签工程层                             │
│    未来第5天涨跌标签 · 历史特征 · 70/30时序切分(不打乱)     │
└──────────────────────┬───────────────────────────────────┘
                       │ 数据
┌──────────────────────▼───────────────────────────────────┐
│           项目一清洗数据（含技术指标）                      │
└──────────────────────────────────────────────────────────┘
```

### 2.5 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|

## 3. 功能需求

### 3.1 特征与标签工程（FR-FEATURE）

#### FR-FEATURE-01 标签定义

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-FEATURE-01 |
| **需求名称** | 预测目标标签定义 |
| **优先级** | 高 |
| **描述** | 将预测任务定义为分类任务：未来第 5 天收盘价 > 今日收盘价记为 1（涨），否则记为 0（跌） |

**功能规则：**
- 标签公式：`label[t] = 1 if close[t+5] > close[t] else 0`
- 采用分类任务而非回归，预测方向更稳定
- 标签构造后需删除因未来数据缺失产生的 NaN

---

#### FR-FEATURE-02 特征选择

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-FEATURE-02 |
| **需求名称** | 预测特征选择 |
| **优先级** | 高 |
| **描述** | 选取历史价格、MA、RSI、MACD、成交量作为特征 |

**功能规则：**
- 特征包括：历史收盘价、MA5/MA10/MA20、RSI、MACD（DIF/DEA/柱）、成交量
- **严格禁止把未来数据当作特征**，防止数据泄露
- 删除含 NaN 的行

**验收标准：** `X_train.shape` 和 `y_train.shape` 确认数据量一致。

---

#### FR-FEATURE-03 时序切分

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-FEATURE-03 |
| **需求名称** | 训练集 / 验证集时序切分 |
| **优先级** | 高 |
| **描述** | 按前 70% / 后 30% 划分训练集与验证集，**绝对禁止打乱顺序** |

**功能规则：**
- 训练集：时间上靠前的前 70%
- 验证集：时间上靠后的后 30%
- 严禁 shuffle，保持时序顺序
- 保证训练集始终在验证集之前，杜绝未来数据泄露

**验收标准：** 训练集与验证集无时间重叠，时序有序。

---

### 3.2 多模型搭建擂台（FR-MODEL）

#### FR-MODEL-01 模型注册

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-MODEL-01 |
| **需求名称** | 多模型注册 |
| **优先级** | 高 |
| **描述** | 用字典注册 3 个模型：逻辑回归、XGBoost、LightGBM |

**功能规则：**
- `models = {}` 字典集中管理
- `lr`：逻辑回归（基准模型）
- `xgb`：XGBoost 分类器（`eval_metric='logloss'`）
- `lgb`：LightGBM 分类器（可选，环境受限时可用随机森林替代）

---

#### FR-MODEL-02 统一训练循环

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-MODEL-02 |
| **需求名称** | 统一训练 + 时序交叉验证 |
| **优先级** | 高 |
| **描述** | 用一个统一循环对每个模型执行 TimeSeriesSplit 训练与评估 |

**功能规则：**
- 使用 `TimeSeriesSplit(n_splits=3)` 时序交叉验证
- 每个模型在每折训练并记录指标
- 统一处理不同模型的评估接口

---

#### FR-MODEL-03 指标记录

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-MODEL-03 |
| **需求名称** | Log-Loss 与 AUC 记录 |
| **优先级** | 高 |
| **描述** | 记录每个模型在验证集上的 Log-Loss 与 AUC |

**功能规则：**
- 计算每个模型的验证集 Log-Loss
- 计算每个模型的验证集 AUC
- 汇总存入结果表

**验收标准：** 打印出每个模型的 Loss 和 AUC 数值（例如：XGB Loss: 0.68, AUC: 0.55）。

---

### 3.3 筛选最优模型（FR-BEST）

#### FR-BEST-01 最优模型选择

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-BEST-01 |
| **需求名称** | 自动筛选最优模型 |
| **优先级** | 高 |
| **描述** | 自动选取 Log-Loss 最小（或 AUC 最大）的模型作为 `best_model` |

**功能规则：**
- 主指标：Log-Loss 最小
- 备选：AUC 最大（Log-Loss 并列时参考）
- 返回最优模型标识与对应指标值

---

#### FR-BEST-02 最新数据预测

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-BEST-02 |
| **需求名称** | 最新数据上涨概率预测 |
| **优先级** | 高 |
| **描述** | 用最优模型对数据集最后一行（最新实时数据）进行预测，得到上涨概率 |

**功能规则：**
- 使用数据集最后一行作为最新实时数据
- 用 `best_model.predict_proba` 得到上涨概率
- 输出概率（例如 62%）

**验收标准：** 控制台输出：“最佳模型是 XGBoost，推荐置信度 62%”。

### 3.4 AI 投资顾问接口（FR-ADVISOR）

#### FR-ADVISOR-01 投资建议 Prompt

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-ADVISOR-01 |
| **需求名称** | 风控导向投资建议 Prompt |
| **优先级** | 高 |
| **描述** | 设计第二份 Prompt（与项目一不同），让 AI 生成保守、风控导向的投资建议 |

**Prompt 模板示例：**
```
基于机器学习模型回测，最优模型历史胜率约为 53%（略高于随机）。
当前预测上涨概率为 {prob}%。当前市盈率 PE 为 {pe}。
请以极其保守、风险中立的语气，给投资者提供三条操作建议，
并明确列出潜在风险因素。
```

---

#### FR-ADVISOR-02 建议生成

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-ADVISOR-02 |
| **需求名称** | 调用大模型生成投资建议 |
| **优先级** | 高 |
| **描述** | 调用大模型获取风控导向的投资建议文本 |

**功能规则：**
- 注入预测概率、历史胜率、PE 等上下文
- 约束输出语气为保守、风险中立
- 至少包含三条操作建议与风险因素

**验收标准：** 建议带有明显风控措辞（如“建议轻仓观望”），而非“满仓杀入”。

## 4. 非功能需求

| NFR-REL-01 | 评估严谨性 | 用 Log-Loss + AUC 双指标互补评估 |

| NFR-REL-03 | 可复现性 | 固定随机种子后多次运行结果一致 |

### 4.5 可维护性需求

| 需求编号 | 需求描述 | 验收标准 |
|---------|---------|---------|
| NFR-MAINT-01 | 模块化 | 特征/模型/训练/评估/建议分层解耦 |

| NFR-MAINT-03 | 可配置 | 折数、特征列表、模型集合可通过配置调整 |

### 4.6 可扩展性需求

| 需求编号 | 需求描述 | 验收标准 |
|---------|---------|---------|
| NFR-EXT-01 | 新增模型 | 在字典追加模型对象即可参赛 |
| NFR-EXT-02 | 新增特征 | 在特征列表中追加即可纳入训练 |

## 5. 数据需求

### 5.1 输入数据

| 字段 | 说明 | 来源 |
|------|------|------|
| date | 交易日期 | 项目一清洗数据 |
| close | 收盘价 | 项目一清洗数据 |
| MA5/MA10/MA20 | 均线 | 项目一指标 |
| RSI | 相对强弱指标 | 项目一指标 |
| DIF/DEA/MACD | MACD 指标 | 项目一指标 |
| volume | 成交量 | 项目一清洗数据 |

### 5.2 工程化数据

| 数据 | 维度 | 说明 |
|------|------|------|
| `features` | 特征矩阵 | 历史价格 + 指标 + 成交量 |
| `label` | 标签向量 | 未来第 5 天涨跌（0/1） |
| `X_train` / `y_train` | 训练集 | 前 70%，时序有序 |
| `X_val` / `y_val` | 验证集 | 后 30%，时序有序 |

### 5.3 输出数据

| 数据 | 说明 |
|------|------|
| 模型评估表 | 每个模型的 Log-Loss、AUC |
| 最优模型 | `best_model` 标识与指标 |
| 上涨概率 | 最新数据预测概率（如 62%） |
| 投资建议 | LLM 生成的 Markdown 风控建议 |

> 本项目在项目一数据基础上运行，不新增独立持久化数据库；评估结果与建议在内存与界面中展示。

| `split_time_series(X, y)` | 70/30 时序切分（不打乱） |
| `train_models(X_train, y_train)` | 多模型统一训练 |
| `time_series_cv(model, X, y)` | TimeSeriesSplit 交叉验证 |
| `evaluate_model(model, X_val, y_val)` | Log-Loss / AUC 计算 |
| `select_best(results)` | 筛选最优模型 |
| `predict_latest(best_model, X)` | 最新数据概率预测 |
| `build_advice_prompt(...)` | 组装投资建议 Prompt |
| `call_llm(prompt)` | 调用大模型 |
